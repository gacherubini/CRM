O problema que ela resolve

por que existe

O monorepo tem seis produtos e cerca de 144 mil linhas de Python. Uma busca às cegas devolve sobretudo lixo: dos 10.288 arquivos da árvore, 93% são código-fonte dos cinco .venv.

Todo agente começa cego, em toda sessão. Sem um índice, ele lê main.py inteiro — o do portal tem 2.609 linhas — e ainda assim não sabe quais armadilhas já custaram caro nem o que o dono já recusou.

A skill é porta, não caminho: entrega o contexto que só ela tem e roteia para quem sabe o resto. Ela não tem protocolo próprio de implementar, propor ou depurar.

O protocolo

o que acontece quando ela dispara

  1. Um produto, dos seis. Tarefa que cruza dois vira conversa com o dono, não código — entre produtos só existe HTTP versionado.
  2. Frescor. --frescor <produto>. Respondeu mapa em dia, segue calado; listou arquivos, diz quantos e oferece regerar.
  3. Abre o mapa do produto, nunca o main.py inteiro. Rota, modelo, worker, migration, flag e template, com o comando de teste nos dois sistemas operacionais.
  4. Lê os dois índices e abre só os que batem com o gatilho — normalmente zero, um ou dois.

As decisões são lidas no passo 4, antes de rotear. Depois já é tarde: a skill destino começa cega e re-propõe o que o dono recusou.

Três camadas, três donos da caneta

quem pode escrever o quê

É a separação que impede a skill de virar mais uma pasta de docs apodrecendo. Cada camada tem um dono da escrita diferente — e uma garantia diferente, que a página anuncia em vez de esconder.

CamadaQuem escreveGarantiaO que é
mapa/ script provado Saída de gerar_mapa.py. Nunca se edita à mão: erro no mapa é erro no gerador.
learnings/
decisoes/		 agente rotulado Por acréscimo, com poda. Armadilha que já custou caro; decisão que não se re-propõe.
SKILL.md humano aprovado O protocolo. A skill não se auto-edita — carrega em todo disparo e derivando sozinha vira 400 linhas que ninguém revisou.

Quando um ensaio achou um defeito no próprio protocolo, ele não se corrigiu: escreveu uma linha em propostas.md e esperou o dono aprovar. Essa é a válvula, e é o que mantém o passo 3 de cima honesto.

Por que o mapa não mente

a diferença entre isto e documentação

Cada linha do mapa é um par arquivo:linha mais o símbolo que tem que estar escrito naquela linha. --verificar reabre todas elas e prova, uma a uma. Documento errado fica quieto; esse falha alto e sai com código 1.

$ python gerar_mapa.py --verificar mapa confere com o codigo $ python gerar_mapa.py --frescor portal-gestao mapa em dia

O contrato é literal: linha > 0 exige o símbolo naquela linha; linha == 0 exige só que o arquivo exista.

Como o mapa é feito

Por análise estática de AST, com a biblioteca padrão. O gerador nunca importa nem executa código de produto — não sobe app, não abre banco, não lê secret.

MóduloPapel
varredura.pyEnxerga o projeto e ignora os cinco .venv. Define o contrato Entrada.
extratores.pyRota, modelo, worker, migration, flag, template — um extrator por seção.
cruzamentos.pyJuntas entre produtos: n8n → chatbot, rota órfã, os fly.toml.
gerar_mapa.pyJunta tudo, renderiza, e implementa --verificar e --frescor.

Frescor sai do commit do mapa

e não do selo, por um motivo

O selo em _frescor.json guarda o SHA de quando o mapa foi gerado — o que é sempre um commit antes do commit que grava o mapa. Comparar a partir dele listava as mudanças do próprio commit certo.

Ou seja: o aviso de "desatualizado" disparava justamente quando o agente tinha acertado — mexeu na rota, regerou o mapa e commitou os dois juntos, como o AGENTS.md §6 manda.

A base agora é git log -1 -- mapa/, o commit que atualizou o mapa por último. O selo continua ali como procedência e como fonte do inventário que o --verificar reabre — só não serve para medir frescor.

Cegueira declarada

a regra que veio de errar seis vezes

O modo de falha que mais se repetiu na construção da skill: o gerador assumia uma forma sintática onde o repo usava duas, devolvia menos e continuava verde. Aconteceu com revision, com os.getenv, com TemplateResponse, com prefix=.

O pior caso: rotas cujo path é variável — @router.get(_PAGINA) — ficavam fora do mapa. Eram 25, e não quaisquer 25: as do Copiloto, do Financeiro e do WhatsApp, ou seja, os módulos novos. E --verificar seguia dizendo que estava tudo certo, porque ele só reabre o que está no mapa.

a regra que sobrou

Ausência num mapa nunca prova ausência no código. Path que o gerador não consegue ler agora vira aviso explícito, ancorado no nome da função. Hoje não dispara para arquivo nenhum — nasce mudo e fala no dia em que aparecer uma forma nova.

O que ela não faz

os limites, declarados

  • Não sabe o estado de produção. Flag ligada é secret. O mapa diz que a flag existe e onde ela é lida, não se está ativa.
  • Os learnings são rotulados, não provados. Cada um declara onde mora a verdade dele — repo se confere lendo código; infra e externo apodrecem sem sinal nenhum no git. A maioria está marcada como nunca reconferida. Trate como pista.
  • Não impede o agente de errar. Ela torna o erro mais barato de pegar, que não é a mesma coisa.
  • Não julga arquitetura. "Não mexa aqui" mora no README.md do produto. O mapa aponta; não copia.

Comandos

Windows usa python; o Mac do dono só tem python3

$ cd .claude/skills/revy-research $ python gerar_mapa.py # regera o mapa $ python gerar_mapa.py --verificar # confere; sai 1 se o mapa mentir $ python gerar_mapa.py --frescor portal-gestao $ python -m pytest test_gerar_mapa.py -q -p no:cacheprovider

Mexeu em rota, modelo, worker, migration ou flag? Regere o mapa e commite junto com o código.
